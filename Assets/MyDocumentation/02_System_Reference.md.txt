# Core Systems

---

# TurnManager

## Purpose

The **TurnManager** is the central gameplay controller.

It manages:

- match flow;
- turn order;
- movement permissions;
- player selection;
- environmental effects;
- communication between gameplay systems.

---

## Responsibilities

- Start the match after `MissionIntro`
- Alternate turns between Player1 and Player2
- Maintain the current player
- Reset movement points
- Highlight valid destinations
- Validate movement
- Apply environmental hazards
- Notify `CameraFollow` when the active player changes

---

## Dependencies

- `PlayerUnit`
- `Map1HexGrid`
- `ClickableSphere`
- `CameraFollow`

---

## Important Methods

```csharp
BeginMatch()

StartNextTurn()

HandleMoveFinished()

HighlightValidMoves()

OnSphereClicked()
```

# PlayerUnit

## Purpose

Represents one playable robot.

Each player robot is an instance of this class.

---

## Responsibilities

- Health
- Shield
- Movement
- Animation
- Environmental damage
- Carrying boxes
- Health bar updates

---

## Components

- Animator
- HealthCanvas
- ShieldBar
- EnergyBar

---

## Important Methods

```csharp
SmoothMove()

TakeEnvironmentalDamage()

UpdateHealthBars()

SetMovementPoints()

ConsumeMovementPoint()
```

# CameraFollow

## Purpose

Controls the gameplay camera after the cinematic introduction.

---

## Features

- Smooth follow
- Mouse-wheel zoom
- Right Mouse orbit
- Automatic target switching
- Recenter (`R`)

---

## Input

| Input | Action |
|--------|--------|
| Mouse Wheel | Zoom |
| Right Mouse | Orbit |
| R | Recenter |

---

## Purpose

---

## Camera Sequence

# ClickableSphere

## Purpose

Represents one legal movement destination.

---

## Responsibilities

- Receive mouse click
- Notify TurnManager
- Destroy itself when movement finishes

---

# HealthCanvas

## Purpose

Displays the current health status of a `PlayerUnit`.

---

## Contains

- Background
- ShieldBar
- EnergyBar

---

## Known Pitfalls

⚠ **ShieldBar** and **EnergyBar** must reference the visible child transforms.

Some objects share identical names, but only one is the actual visible bar.

Assigning the wrong transform causes the health bars to stop updating even though the gameplay values change correctly.
